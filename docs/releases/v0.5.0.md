# 讯港 · NotiHarbor v0.5.0

**A Reliable, Self-Hosted Notification Gateway**  
**可靠、自托管的统一消息通知网关**

NotiHarbor 首个独立发行版本，基于 JustSong 的 Message Pusher 衍生，保留 MIT 许可证及原项目版权。版本号接续原项目的 v0.4.x 系列。

## 本次更新

- 统一通知 API：source/API key/scope 权限隔离、幂等提交、多通道路由、通知历史与审计。
- 可靠异步投递：SQL 事务 outbox、Redis Streams、持久化发送尝试、重试、死信和 fallback；发送结果未知时不自动重发。
- QQ 官方 Bot v2：C2C/群聊普通主动发送、已验签回调中的被动回复和独立 C2C wakeup 模式。普通主动发送不要求近期回调，但仍受机器人权限、目标关系、用户设置及平台限额约束。
- SMTP 邮件及自定义 HTTPS Webhook，凭据加密、请求安全限制和发送错误分类。
- Web 管理界面：Dashboard、来源与 API key、目标、通知详情、日志及通道测试器。
- Session、同源请求校验、旧接口认证、弱默认密码和日志脱敏改进；保留 `/push/{username}` 等兼容入口。
- 讯港品牌、README、部署与迁移文档更新，保留原项目来源、版权与致谢。

## 容器镜像

支持 **linux/amd64** 和 **linux/arm64**，推荐部署固定版本：

```bash
docker pull ghcr.io/jung233/notiharbor:v0.5.0
```

持续更新标签：`ghcr.io/jung233/notiharbor:latest`。若 GHCR package 为私有，拉取前需使用具备 `read:packages` 权限的账号登录。

完整配置见 [部署指南](https://github.com/jung233/NotiHarbor/blob/v0.5.0/docs/deployment.md) 和 [.env.example](https://github.com/jung233/NotiHarbor/blob/v0.5.0/.env.example)。Compose 默认从源码构建；使用已发布镜像时设定 `NOTIHARBOR_IMAGE=ghcr.io/jung233/notiharbor:v0.5.0`，并用 `docker compose up -d --no-build` 启动。

## 升级与验证

升级前备份数据库并妥善保存同一把 `ENCRYPTION_KEY` 和稳定的 `SESSION_SECRET`。现有凭据会自动迁移加密；回滚旧版需同时恢复升级前数据库。初始管理员密码至少 12 个字符。详细步骤见 [迁移指南](https://github.com/jung233/NotiHarbor/blob/v0.5.0/docs/migration.md)。

此 Release 仅在 GitHub Actions 的静态检查、前后端回归测试、临时 MySQL/Redis 集成测试、原生双架构镜像构建及 manifest 发布全部成功后创建。测试使用 mock provider；真实 QQ、SMTP 和 Webhook 发送尚未进行平台验收。
