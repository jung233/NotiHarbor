# 讯港 · NotiHarbor v0.5.1

本次补丁版本收紧访客界面、修复消息实时连接，并改进通知测试与发送日志展示。

## 本次更新

- 未登录时仅展示简洁首页及登录、注册入口，隐藏业务导航、运行统计和配置；私有页面使用登录守卫，用户管理和网关入口使用管理员守卫。
- 登录完成后返回原先访问的页面，身份恢复期间等待服务端会话校验。
- 消息 SSE 连接立即发送首包，每 15 秒发送心跳；支持同一用户的多个连接，关闭旧连接不再移除新连接。
- 修复前端重连计时器清理，减少重复断线提示；消息加载失败恢复加载状态，翻页与实时消息按 ID 去重。
- 通道测试器仅展示应用已授权的通道，实际发送失败时显示失败，并为 QQ 错误码 40011028 提供目标检查提示。
- 发送日志显示尝试次数和类型，明确同一投递的多次尝试各占一行，消息历史按逻辑通知展示。
- 更新 README 的镜像部署说明及功能介绍。

## 容器镜像与升级

支持 **linux/amd64** 和 **linux/arm64**：

```bash
docker pull ghcr.io/jung233/notiharbor:v0.5.1
```

将现有部署的镜像标签从 `v0.5.0` 改为 `v0.5.1`，拉取镜像后重新创建容器。Compose 部署可设置 `NOTIHARBOR_IMAGE=ghcr.io/jung233/notiharbor:v0.5.1`，然后执行：

```bash
docker compose pull
docker compose up -d --no-build
```

保留原有数据库、数据目录、`ENCRYPTION_KEY` 和 `SESSION_SECRET`。升级前备份数据；无需为本次修复重新创建账号或通道。完整配置见[部署指南](https://github.com/jung233/NotiHarbor/blob/v0.5.1/docs/deployment.md)。

## 验证

包含修复的 main 构建已通过静态检查、前端回归、Go 及临时 MySQL/Redis 集成测试，并发布双架构镜像。本次版本标签也会独立执行完整流水线，仅在镜像及多架构 manifest 发布成功后创建 Release。

部署实例已完成 QQ 官方 Bot v2 单聊回调采集与主动消息发送验证，平台返回 HTTP 200 和 `accepted`。该验证依赖实例自身的机器人授权及目标关系；用户仍需配置各自机器人的回调和正确 OpenID，本版本不会自动变更部署实例的机器人配置。
